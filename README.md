# 食遇校园 · AI 智能食堂

> 解决「每天不知道吃啥」的校园食堂 AI 推荐应用。
> 输入口味偏好（爱吃辣 / 清淡 / 不吃香菜 / 预算多少），调用大模型 API，从食堂窗口菜品里智能匹配出今天该吃的那几道菜，并给出推荐理由。

本项目为 uni-app（Vue3）**纯前端 + uniCloud 云函数**架构，无需自建服务器，在 HBuilderX 里关联服务空间即可运行与发行。

---

## 一、核心功能

| 模块 | 说明 |
| --- | --- |
| **AI 智能推荐** | 一句话描述（"想吃辣的，20 块以内，不要香菜"）+ 精细筛选（用餐时段 / 口味 / 忌口 / 预算 / 食堂），云端调用大模型返回 3~5 道菜、推荐理由与匹配度 |
| **忌口硬过滤** | 忌口食材在**服务端二次校验**，即使大模型产生幻觉推荐了含忌口食材的菜，也会被校验环节剔除 |
| **降级兜底** | 未配置 Key / 大模型超时 / 云空间不可用 → 自动降级为本地规则引擎，功能始终可用（首页与推荐页会标注当前数据来源） |
| **菜品浏览** | 菜品列表（搜索 / 食堂 / 分类 / 排序 / 分页）、菜品详情、榜单（热门 / 高分 / 新品） |
| **评价体系** | 星级 + 文字评价，需管理员审核通过后公开展示 |
| **口味档案** | 自动记住上次偏好，下次进入推荐页一键复用，并保留最近推荐历史 |
| **管理后台** | 数据看板、菜品增删改、评价审核、**AI 配置（大模型 Key / 模型 / 中转地址）**、菜品库初始化 |

## 二、技术架构

```
┌─────────────────────────── uni-app 前端（Vue3 + script setup） ───────────────────────────┐
│  首页 / AI推荐 / 菜品列表 / 菜品详情 / 评价 / 我的 / 管理后台                                  │
│                              ↓ 只依赖统一适配层                                              │
│                        api/index.js（统一 API 适配层）                                       │
└───────────────────────────────────┬──────────────────────────────────────────────────────┘
                                    │ ① 主链路：uniCloud 云函数
                                    ▼
        ┌───────────────────────────────────────────────────────────────┐
        │  shiyu-recommend   AI 推荐（Prompt 构建 → 大模型 → 严格校验）    │
        │  shiyu-dish        菜品查询 / 榜单 / 食堂分类 / 增删改            │
        │  shiyu-config      AI 配置读写（Key 不下发客户端）+ 连通性测试     │
        │  shiyu-review      评价发布 / 查询 / 审核                        │
        │  shiyu-seed        菜品库初始化（sync 补齐 / reset 重置）         │
        └───────────────────────────────┬───────────────────────────────┘
                                        │ HTTPS（OpenAI 兼容协议）
                                        ▼
                        大模型 API（DeepSeek / 通义千问 / Kimi / 智谱 / 任意中转）

                         ② 兜底链路（云函数不可用时）
        common/local-dishes.js（40 道本地菜谱）+ common/recommend-engine.js（客户端规则引擎）
```

### 为什么这样设计

- **主链路走云函数**：`uniCloud` 由 DCloud 托管，免运维、免备案，答辩演示不需要现场启动任何后端进程；同时大模型 API Key 只存在于云端，符合"密钥不出服务端"的安全要求。
- **兜底链路走本地规则引擎**：把推荐能力做成"可降级"的，网络异常或未配置 Key 时应用依然完整可用，避免演示翻车。
- **统一适配层**：页面只依赖 `api/index.js` 的语义化方法，不关心数据来自云函数还是本地，后续更换后端实现（例如换成自建 FastAPI）不需要改动任何页面。

## 四、快速开始

### 方式 A：纯本地运行（无需云空间，立刻可看效果）

1. 用 **HBuilderX 3.7+** 打开本项目目录
2. 运行 → 运行到浏览器 / 微信开发者工具 / 手机模拟器
3. 进入「AI 推荐」页，输入口味与预算，点「✨ 生成推荐」

此时走的是**本地规则引擎**（40 道内置菜品），页面底部会提示"当前使用本地离线数据"。想体验真实大模型，按方式 B 配置。

### 方式 B：接入大模型（完整链路）

1. **开通 uniCloud 服务空间**：HBuilderX 左侧项目树 → `uniCloud-aliyun` 右键 → 关联云服务空间（阿里云，免费空间足够）
2. **上传云函数**：右键 `uniCloud-aliyun/cloudfunctions` 下每个 `shiyu-*` 目录 → 上传部署
3. **上传数据库 Schema**：右键 `uniCloud-aliyun/database` 下 3 个 `*.schema.json` → 上传 DB Schema
   （`shiyu-config` 的权限为全 `false`，这是有意为之：Key 只允许云函数读写）
4. **初始化菜品库**：运行项目 → 我的 → （用管理员身份进入）管理后台 → 数据初始化 → 「同步菜品库」
   或在云函数控制台直接运行 `shiyu-seed`，参数 `{"action":"reset"}`
5. **配置大模型 Key**：管理后台 → AI 配置 → 选择服务商（DeepSeek / 通义千问 / Kimi / 智谱 / 自定义中转）→ 填入 `api_key` → 保存 → 点「测试连接」
6. 回到 AI 推荐页重新生成，结果卡片会显示 `大模型 deepseek-chat` 标签

> 也可以在 uniCloud 云函数控制台给 `shiyu-recommend` 配置环境变量 `AI_API_KEY` / `AI_BASE_URL` / `AI_MODEL`，
> 云函数会优先读取数据库配置，读取不到时回退到环境变量。

### 管理员入口

管理员身份**不能自行选择**，必须通过账号口令认证：

1. 登录页（`pages/login/login`）选「管理员」，输入账号与口令
2. 云函数 `shiyu-config` 校验通过后签发一个 HMAC 签名、7 天过期的凭证
3. 只有拿到凭证才会写入本机 `role: 'admin'`，管理后台各页进入时也会再向云端验签一次

默认账号 `admin` / 口令 `admin123`，**登录后请立刻到「管理后台 → AI 配置 → 管理员口令」修改**。
口令以 SHA-256 哈希保存在云端（不存明文），且签名里掺了口令摘要 —— 所以改口令后此前签发的凭证会立即全部失效。

也可以用云函数环境变量覆盖：`ADMIN_USERNAME` / `ADMIN_PASSWORD` / `ADMIN_SECRET`
（配了 `ADMIN_PASSWORD` 就只能去 uniCloud 控制台改口令，页面里的修改会被拒绝并说明原因）。

> 忘记口令的恢复办法：uniCloud 控制台 → 云数据库 → `shiyu-config` → 删掉 `admin_password_hash` 字段，
> 即会重置回默认口令 `admin123`。

普通同学不需要注册账号：昵称 / 头像 / 口味档案 / 推荐历史都保存在本机，仅用于评价与收藏归属。

## 五、AI 推荐链路详解

`uniCloud-aliyun/cloudfunctions/shiyu-recommend/index.js` 的完整流程：

1. **参数归一**：接收 `pref`（结构化偏好）与 `text`（一句话描述），服务端再次解析 `text` 并合并，显式传入的 `pref` 优先
2. **候选集裁剪**：只取 `status == 1` 的菜品，按预算与食堂过滤；再在 JS 层**剔除 tags 命中忌口的菜品**（第一道硬过滤）
3. **读取配置**：`shiyu-config` 集合 → 环境变量，两级回退；没有 Key 直接走本地规则引擎
4. **Prompt 构建**：把同学需求 + 候选菜品 JSON 列表拼成中文 Prompt，明确要求"只输出 JSON"、"严禁推荐含忌口食材的菜"、"dish_id 必须来自候选列表"
5. **调用大模型**：OpenAI 兼容协议 `POST {base_url}/chat/completions`，超时 30s
6. **输出严格校验**（关键工程点）：
   - 容忍 ```json 代码块包裹、前后多余文字
   - `dish_id` 必须存在于候选集，否则丢弃
   - 菜品 tags 不得含忌口词，否则丢弃（防模型幻觉）
   - 价格不得超过预算，否则丢弃
   - 校验后为空 → 降级本地规则
7. **埋点与返回**：命中菜品 `recommend_count` 累加（失败不影响主流程），返回结果并标注 `engine: 'ai' | 'local'`

## 六、数据来源标识

接口返回都会带 `engine` 字段，页面据此提示用户：

| engine | 含义 | 页面提示 |
| --- | --- | --- |
| `ai` | 大模型成功生成并通过校验 | 标签「大模型 xxx」，本次结果由大模型生成 |
| `cloud` | 云函数规则引擎（未配置 Key 或模型调用失败） | 提示可在管理后台配置 Key |
| `local` | 云空间不可用，走前端本地数据 | 当前为本地离线数据 |

## 八、菜品配图

### 推荐方式：后台上传（无需任何脚本）

**管理后台 → 菜品管理 → 编辑（或新增）→ 菜品图片 → 📷 上传图片**

- 从手机相册选图或直接拍照，图片上传到 **uniCloud 云存储**
- 菜品记录里存的是云存储的 `fileID`（`cloud://` 开头），**不是**临时地址，所以不会过期
- 也可以手填图片地址（`static/dishes/d001.jpg` 这类本地路径，或一个 `https://` 外链）
- 点「清除」即可去掉图片，回退成 emoji 占位

### 一个容易踩的坑：fileID 不能直接塞进 `<image>`

`cloud://` 的 fileID 必须先用 `uniCloud.getTempFileURL()` 换成临时地址才能显示
（DCloud 自己的 `uni-id-pages/components/cloud-image` 就是这么做的）。

本项目把这件事收在 **`components/DishImage/DishImage.vue`** 里：它会自动识别 `cloud://`
并换取临时地址，还带一层跨组件缓存（首页榜单同一张图出现三次只会解析一次），
解析失败或图片被删时自动回退成 emoji 方块，不会留破图。

因为首页、菜品列表、菜品详情、菜品管理、数据看板**全部**通过这个组件渲染图片，
所以只要改这一个地方，所有界面都支持上传的图了。

### 图片缺失时

统一回退为 emoji 渐变方块（优先用菜品自己的 emoji 字段，其次取菜名前两字），不会出现破图。

### 真机上传失败？

微信的 **`uploadFile` 合法域名**和 **`request` 合法域名**是**两个不同的列表** ——
云函数调用需要前者，上传图片需要后者里的 `uploadFile` 那一项。

真机上传报 `url not in domain list` 时，到微信公众平台 →
开发管理 → 开发设置 → 服务器域名 → **uploadFile 合法域名** 里补上云存储的域名。

> 说明：早期版本这里写过 `scripts/dish-image-map.json`、`scripts/download-dish-images.mjs`、
> `scripts/self-check.mjs` 三个脚本，但它们**从未提交进仓库**，已按实际情况删除说明。
> 现在配图只需要上面的后台上传。

## 九、常见问题

**Q：运行后没有任何菜品数据？**
先执行「管理后台 → 数据初始化 → 同步菜品库」。若未关联云服务空间，前端会自动使用内置的 40 道本地菜品，功能不受影响。

**Q：首页能看到「第一食堂」，点进去却一道菜都没有？**
这是**云端菜品库里残留了旧版本数据**导致的：旧数据没有 `status` 字段，而菜品列表查询带 `where({status: 1})`，于是查不出来；食堂列表不带这个条件，所以仍然显示。
修复方式（任选其一）：
1. 管理后台 → 数据初始化 → **同步菜品库**（会自动把缺失 `status` 的记录补为 `status: 1`，并提示修复条数）
2. 或直接执行 **重置菜品库** 全量重建
3. 或到 uniCloud 控制台把 `dishes` 集合清空后重新同步

另外适配层已加保护：当检测到云端菜品库为空或含有本地不认识的食堂（说明数据陈旧）时，会整体退回本地 40 道菜谱，不会再出现"有食堂没菜"的空列表。

**Q：点「生成推荐」提示未配置 API Key？**
到「管理后台 → AI 配置」填写。也可以在 uniCloud 云函数控制台配置 `AI_API_KEY` 环境变量。Key 不会下发到客户端。

**Q：测试连接返回 401 / 404？**
401 = Key 无效或已欠费；404 = `base_url` 写错（注意要带 `/v1` 这类版本路径）或 `model` 名称不存在；超时 = 网络受限或中转地址不可达。

**Q：小程序真机访问不了？**
云函数不需要配置域名白名单；若使用自建后端（`backend/`）则需在微信后台配置 request 合法域名。

**Q：`backend/` 目录是必须的吗？**
不是。那是早期自建 FastAPI 后端的备用实现，默认不参与运行，前端已不再依赖它。保留它是为了说明"同一套前端可以对接不同后端实现"的可扩展性，详见 `backend/README.md`。
